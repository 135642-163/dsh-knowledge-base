# 0.33 路线图：知识库搬运与整体设计缺口（2026-10-31）

> 本文回答"从插件整体设计看，接下来还需要做什么"，并把用户提出的**知识库导出/导入（搬运）**写成可执行设计。
> 当前版本 0.32.0（本轮：标准更新链路修复、版本收敛规则、封面代替关系、数据治理）。

## 1. 现状盘点（0.32.0）

| 层 | 已有能力 | 缺口 |
|---|---|---|
| 资料入库 | `kb_import`（docx/ppt/xlsx/pdf/epub/mobi/txt；扫描件 OCR；跨库查重；后台任务）、`kb_reparse` | 导入前预览/纠错较弱；大包批量导入无进度恢复 |
| 阅读/检索 | `kb_query`（BM25 + 条款索引）、`kb_read/kb_view`（分页、原件图）、语义检索开关（默认 off） | 语义检索收益未验证；检索结果缺"主题聚合" |
| 维护 | `kb_edit/kb_edit_batch/kb_describe/kb_retitle/kb_trust/kb_keep/kb_lint/kb_snapshot/kb_history` | **快照只有"建"没有"恢复"工具** |
| 标准自动化 | `kb_std_check`（检查/下载/防串档/每日限额）、`scripts/fetch-standards.mjs`、版本收敛（年份/封面代替） | 缺定时检查；缺口清单（站点未收录）无持久跟踪 |
| 交付 | `kb_export`（md / jsonl 分块 / zip / Obsidian vault） | **导出的 zip 没有对应的"导入/还原"入口**（本机→他人机器走不通） |
| 工作台 UI | 标准更新面板、资料弹窗（改标题/标准号）、检索 | 无导出/导入包入口；替代链无可视化 |
| 安全 | Cookie 存 profile 明文；导出做路径脱敏 | 凭证明文存储可改进（钥匙串/系统凭据） |

## 2. 优先级建议

| 优先级 | 事项 | 价值 | 规模 |
|---|---|---|---|
| **P0** | 知识库包导出 → 导入（搬运闭环） | 用户明确需要；团队共享/换机的前提 | 1–2 天 |
| **P0** | `kb_snapshot_restore`（快照恢复工具化） | 现在恢复要手写解压，易错 | 0.5 天 |
| P1 | 标准自动化收尾：定时检查 + 缺口清单 + 工作台入口 | 已经修好链路，差"按时跑、有台账" | 1 天 |
| P2 | 交付包（按主题/客户裁剪的导出：选库/选文档/摘要+目录+引用页） | 对外交付更可控 | 1 天 |
| P3 | 语义检索评估（off/on 对比，p95 < 120ms 才考虑默认开） | 提升召回，但收益未验证 | 1–2 天 |
| P4 | 凭据进钥匙串、工作台替代链可视化 | 安全/可解释性 | 各 0.5 天 |

## 3. P0 设计：知识库包（`kbpack`）

### 3.1 包格式（`kb_export format=zip` 已产出的结构，需补清单）

```
my-kb-export.zip
├── manifest.json        # 包清单：schemaVersion / kbName / exportedAt / exporterVersion / counts / docs[]
├── kb.json              # 原库清单（可选：导入时以 manifest 为准）
├── markdown/<docId>/…   # 派生分块（无源文件模式下的正文）
├── sources/…            # 原始文件（includeSources=true 时）
├── schema.md / log.md / index.md
└── snapshots/…（可选）
```

`manifest.json` 关键字段：

```json
{
  "format": "kbpack/v1",
  "kbName": "标准",
  "exportedAt": "2026-10-31T…",
  "exporter": { "plugin": "dsh-knowledge-wiki", "version": "0.33.0" },
  "withSources": true,
  "counts": { "docs": 919, "notes": 7, "bytes": 123456789 },
  "docs": [
    { "id": "c26c26b2051e", "title": "GB/T 12326-2008 …", "standardNo": "GB/T 12326-2008",
      "sourceHash": "…", "chars": 10744, "pages": 15, "trust": "high",
      "sourceFile": "GBT 12326-2008.pdf", "hasSource": true, "hasMarkdown": true }
  ]
}
```

### 3.2 导入接口

新工具 `kb_import_package`（`kb_import` 遇到 `.zip` 时也自动路由到它）：

```
kb_import_package({ path, kb?, mode? })
  kb:    目标库名（省略 = 用包内 kbName；已存在则进入合并流程）
  mode:  merge（默认）| rename（导入为新库，冲突自动加后缀）| replace（覆盖同 id 文档，需 confirm）
```

导入步骤（全部在 `withManifestLock` 内）：

1. **校验**：`format==="kbpack/v1"`；`schemaVersion` 不高于本插件；解压到临时目录，拒绝 `..` 路径穿越与符号链接；
2. **冲突处理**：
   - 同 `id` 且 `sourceHash` 相同 → 跳过（幂等，重复导入不产生新文档）；
   - 同 `id` 但内容不同 → 重新分配 docId（`docIdFor(relKey + "~imported")`），保留两份并写 `warnings`；
   - 同标准号/标题但不同 id → 走 `kb_import` 的 dedup 逻辑（默认跳过，报告跨库重合；`allowCrossDuplicates` 可强制）；
3. **落盘**：源文件写 `sources/`；markdown 写 `markdown/<docId>/`（若包内无 markdown 但有 sources → 走 `kb_reparse` 重新解析）；
4. **合并元数据**：以包内 `title/standardNo/stage/trust/tags/summary` 为准；`*Source=manual` 的字段不覆盖目标库已有的人工值（与现有规则一致）；
5. **重建索引**：`refreshKbIndex` + FTS 重建（大库转后台任务，带进度）；
6. **记账**：`log.md` 写一条 `import-package`（包名、篇数、跳过数、冲突数），`kb_lint` 立即可查。

### 3.3 安全与体量

- 包内**不含** `bzCookie`、`.std-check.json`、`.preview/`、`history/`（可选 `--with-history`）；
- 路径脱敏沿用 `redactPaths`；压缩率与内存：解压流式（`jszip` 流式或 `unzipper`），大包走后台任务；
- 包可加密（可选 P1）：`--password` 用 `age`/`zipcrypto`，仅防护误传。

### 3.4 验收

- 单元：包校验（坏包/穿越/版本过高）、id 冲突重映射、幂等重复导入、跨库查重提示；
- 端到端：本机导出 `标准`（含 sources）→ 临时 kbRoot 导入 → `kb_query` 命中数、`kb_list` 篇数、`kb_lint` 无新增问题；
- 体量：920 篇 / 85MB 的包在 5 分钟内导入完成（后台任务可续）。

## 4. P1 标准自动化收尾

1. **定时检查**：用宿主 schedule 能力（或 macOS launchd 示例脚本）每天跑一次 `kb_std_check action=check`，
   结果落 `docs/reports/std-check-YYYYMMDD.md`；有 `update/released` 才提醒。
2. **缺口台账**：把「站点未收录（非站外体系）」与「分册歧义」写进 `<kb>/.std-gaps.json`，跨轮追踪；
   站点后续收录时自动从台账里移除。
3. **工作台入口**：标准更新面板加"补下载指定编号"（复用 `findStdOnSite`）与"替代链"展开。

## 5. P2 交付包

- `kb_export format=deliver`：选库/选文档/选主题 → 输出 `README.md + 目录 + 摘要 + 每篇正文（含页码锚点）`，
  可选 `--max-chars` 分卷；面向"发给客户/同事的阅读包"，与 `kbpack`（迁移包）区分。

## 6. 建议执行顺序

1. `kbpack` 导出清单补齐 + `kb_import_package`（P0，本轮之后立刻做）；
2. `kb_snapshot_restore`（P0，半天）；
3. 标准更新定时检查与缺口台账（P1）；
4. 交付包（P2）；
5. 语义检索评估（P3，需先定验收线）。
