## 本轮为达标做的两处实现调整（都不是按题号特判）

1. **强词面命中的标题条件**：`keywordsOfQuery` 会切出「光伏并网逆变器功」这类长片段，纯子串命中会漏掉
   标题只含「光伏」的文档（Q12：H 第 9 → K 第 1）。改为「标题命中任一检索词 **或与查询共享任一 CJK
   二字片段**」，其余两条（条款命中 ≥2 个不同词、trust != low）不变。这是唯一调参处，在 60 主集与
   20 独立题上同时验证：条款 MRR 0.772 → 0.883，同义改写 Doc Recall 保持 80.0%（锁定只改排序，不改召回）。
2. **两阶段页码从「文档内 FTS」改为「文档内按词命中扫描条款」**：原方案每篇文档跑一次
   `WHERE doc_id = ?` 的 FTS 查询，实测 **17.6ms/篇**（p95 23.1ms），top-10 × 80 题把 p95 推到 160ms+；
   改为 `clauses(doc_id)` 索引 + 文档内条款扫描（文档内按查询词命中数排序），实测降到 **69ms p95**，
   语义不变（仍是「在该文档内找条款命中」）。`clauses_doc_id_idx` 在首次打开旧索引时惰性创建
   （标准库 149k 条款约 1.1s，一次性）。

## 其它口径说明

- **Page Recall 沿用 0.30 定义**：文档进 top-10，且该文档任一命中条款的页码区间覆盖期望页。
  K 的页码候选 = B 文档的全部条款命中页 ∪ dense 独有文档「文档内词命中条款」的前 5 页；
  页面卡片仍只展示最佳条款的单页（`page`/`pageEnd`）。
- **召回集合不变**：只融合 B 的 top-50 与 dense top-50，B 第 51 名之后按原序追加在末尾
  （单测覆盖：55 篇文档时结果仍为 55 篇）。

## 0.31.1 真实嵌入延迟复测

`--semantic-sim` 不含模型嵌入。0.31.1 用 `scripts/eval/semantic-latency.mjs` 复测生产等价路径：
真实 D1a 运行时（onnxruntime-node + tokenizer + bge-small-zh-v1.5）+ 真实 B 检索 + 两阶段页码
（`lib/search.js` / `lib/fts-index.js`），文档向量仍用 0.30 的 911×512 矩阵，索引复制到临时目录
（不写真实库）。

| 项 | 80 题实测 |
|---|---|
| 语义融合实际生效 | 80 / 80 |
| 总延迟（B + 嵌入 + 融合/页码） | mean 42.09ms / **p50 42.4ms / p95 58.21ms** / max 65.47ms |
| 其中 B（FTS + boost） | mean 38.53ms / p95 54.63ms |
| 其中查询嵌入（真实模型） | mean 2.25ms / p95 2.83ms |
| 其中融合 + 两阶段页码 | mean 1.31ms / p95 2.11ms |
| 模型 + session 加载 | 85.8ms（冷启动一次） |
| 进程 RSS | 284MB |

结论：开启语义后 p95 **58.2ms**，远低于 120ms 门槛（HTTP/UI 开销另计约几毫秒）；模型热态后每次查询
只多约 3.5ms（嵌入 + 融合/页码）。复现：

```bash

  --doc-vectors /tmp/kb-eval-030/vec-docs \
```
