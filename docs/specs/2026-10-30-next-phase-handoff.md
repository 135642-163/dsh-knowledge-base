## 2. 安全与硬约束

1. **真实知识库默认只读**。任何写操作（改名、摘要、信任度、删除、重解析、导入、移动）必须先：
   - 明确告诉用户影响范围；
   - 用 `kb_snapshot` 留库级快照（大库可只留 `kb.json` + 必要文件，说明局限）；
   - 小批量（建议 ≤20 篇/批）执行并回报结果。
2. 不改手工数据：
   - `summarySource=manual` 的摘要、`titleSource=manual` 的标题、`trustSource=manual` 的可信度，批量脚本必须跳过（除非用户逐条确认）。
3. 测试一律用临时 `kbRoot`，不要拿真实库跑单测。
4. 不提交/推送，除非用户明确说「提交/推送」。
5. 不重写/覆盖 `docs/specs/` 下已有的评测报告；新报告另起文件名。
6. 不改 viewer / 回收站 / 会话胶囊 / 导入核心行为，除非任务明确要求。
7. 所有批量操作可回滚：记录快照名、文档 id、前后值。

## 3. 四个工作流（按优先级）

### 优先级 1：知识库质量治理（先做，默认只读）

**目标**：先产出一份可信的「问题清单」，再和用户确认后分批修复。

1. 写只读审计脚本（建议 `scripts/quality-audit.mjs`，不写库）：
   - 逐库统计：失败文档、导入中、低可信、OCR 低置信页、文字层损坏页、0 页/0 字文档、摘要为空或明显乱码（含 `�`、大量单字母碎片）、标题异常（像标准但无 standardNo、重复编号）；
   - 复用 `kb_lint` 的分组：内容重复、同标准号同期同阶段重复、同号多版本、未编目、笔记无来源、孤页、缺少 schema；
   - 输出机器可读 JSON + 人类可读 markdown 报告（放 `docs/reports/`）；
   - 每类问题给出建议动作（kb_reparse / kb_describe / kb_remove / kb_keep / kb_trust / 重新导入）。
2. 先只报告，不改真实库；把「建议立刻处理的 Top 10」列给用户。
3. 用户确认后再分批修复，每批：
   - 快照；
   - 执行（例如重解析低置信页、补摘要、坏文件换源/回收站、重复组 kb_keep 或删除）；
   - 重新跑审计，确认该类问题下降；
   - 记录结果与回滚方式。

**验收**：
- 审计脚本有单测（用临时知识库 fixture，覆盖失败/低可信/损坏/重复/零页等）；
- 报告能准确列出问题与数量；
- 修复批次前后对比可见，手工数据零误改。

### 优先级 2：标准更新自动化

- 先查 `kb_std_check` 配置与 `bzCookie` 状态；没有 Cookie 时只做 `check` 报告，不下载。
- 先 `limit` 小批量（如 20 个编号）跑 check，核对：
  - 标准号/年份是否识别正确；
  - 新版封面是否写明「代替 <旧版号-年>」；
  - 报批稿/征求意见稿不能作为废止依据。
- 用户确认后再下载导入；同一标准号多版本要保留旧版并标 `trust=low`（有代替关系时），不要直接删。
- 单测用假 HTTP/固定夹具，不真连标准网；真实下载单独跑并回报。

**验收**：check 报告准确、下载文件可解析、旧版处理符合规则、无重复导入。

### 优先级 3：语义检索评估/开启

- 现有可选语义层（0.30–0.31.2）默认关闭；本机组件与模型已就绪。
- 用现有评测脚本跑 80 题，对比 off/on：
  - Doc Recall@10、Page Recall@10、MRR@10、条款定位 MRR；
  - 20 条独立改写集的 Doc Recall；
  - 查询 p95（目标 <120ms）。
- 基线（0.31.0）：H 84.4 / 74.4 / 0.603；K 84.4 / 77.5 / 0.613；独立集 80.0%；真实 embed p95 58.2ms。
- 若开启后收益不明确或 p95 超标，保持 off；若开启，先在真实库小范围验证再全局开，保留一键关闭。

**验收**：评测报告、延迟数据、开启/回滚步骤；off 行为与 0.30 完全一致。

### 优先级 4：对外交付与新功能

- 候选（待用户定）：
  - `kb_export`：md 单文件 / jsonl 分块 / zip / Obsidian vault；
  - 面向其他大模型的资料包与引用规范；
  - 常用专题的编译笔记（实体/概念/专题）。
- 先定义交付物和验收标准，再实现；不为了做功能而做功能。

## 4. 建议的执行顺序

```
1.1 只读审计 → 1.2 用户确认 Top 问题 → 1.3 分批修复
→ 2.1 标准更新 check（只读）→ 2.2 小批量下载导入
```
