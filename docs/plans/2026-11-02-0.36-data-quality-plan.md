# 0.36 数据质量工作台 + 清理 Runbook（计划）

- 基线：0.35.2（tag `v0.35.2`，commit `c02d98d`）
- 真实库：`/Users/littlesun/workspace/knowledge/标准`（929 篇，891 在库，38 软删除）
- 目标：把 `kb_lint` 的机械体检结果变成可筛选、可预览、可分批执行的“质量队列”，
  并为 `标准` 库写一份**包含人工判断步骤**的清理 Runbook。
- 本计划只做设计和实现顺序，不在本文件执行数据清理。

## 1. 边界与原则

### 自动化做什么

- 聚合 `lintManifest` 的机械结果：失败、坏页/低置信、正文不完整、内容重复、同号多版本、
  未编目、无来源笔记、旧管线、临时文件等；
- 提供证据字段、分页/筛选、按文档跳转 `kb_view`/`kb_read`；
- 提供**预览 + dry-run + 批量执行**（重解析指定页、重试失败、补摘要、标可信度、
  `kb_keep`、软删除）；
- 每次写操作记 log、刷新索引，默认软删除可恢复。

### 人工判断必须保留

以下不做自动决策，Runbook 中逐项列出人工步骤：

- 坏页里是表格/图形/空白：先 `kb_view` 核对，可读则保留 flag，不重复 OCR；
- 正文不完整：判断是文字层失败、封面-only 还是源文件缺页；缺源不编造；
- 摘要：先读首页/范围句，再写 1–2 句；扫描件无正文时用封面信息，不能编造；
- 标准号/前缀：必须有封面证据；站点记录与封面冲突时以封面为准，过程稿不改；
- 同号多版本：判断是否保留两份、是否把旧版标 low；报批/征求意见稿不能当废止依据；
- 删除/合并笔记：人工确认，默认软删除。

## 2. 数据模型与 API

### 2.1 质量读模型

`GET /kb/api/kbs/:name/quality?maxItems=100&staleDays=90`

返回：

```json
{
  "kb": "标准",
  "generatedAt": "ISO",
  "summary": {
    "totalDocs": 891,
    "groups": 13,
    "error": 0,
    "warning": 58,
    "info": 120,
    "actionable": 48
  },
  "groups": [
    {
      "code": "corrupted",
      "label": "文字层损坏 / OCR 低置信",
      "severity": "warning",
      "count": 48,
      "hint": "关键页用 kb_view 核对；必要时 kb_reparse forceOcrPages=…",
      "items": [
        {
          "docId": "...",
          "title": "GB/T ...",
          "detail": "损坏 3 页，低置信 0 页",
          "pages": [39, 40, 41],
          "contentIntegrity": "full",
          "suggestedAction": "reparse-pages"
        }
      ],
      "truncated": false
    }
  ]
}
```

- 复用 `lintManifest(manifest, {kbName, hasSchema, staleDays, maxItems})`，不复制判定逻辑；
- 每项补充 `pages`、`contentIntegrity`、`summaryMissing`、`trust`、`readOnly` 等证据字段；
- `maxItems` 控制每组的明细条数，`count` 始终是总数；
- 只读接口；不写任何文件。

### 2.2 质量动作

`POST /kb/api/kbs/:name/quality/actions`

```json
{
  "action": "reparse-pages",
  "ids": ["docId1", "docId2"],
  "params": { "pages": [39, 40, 41] },
  "dryRun": true
}
```

动作白名单（P0）：

| action | 参数 | 行为 |
|---|---|---|
| `retry-import` | ids | 失败文档重试/重解析 |
| `reparse-pages` | ids + pages | 对指定页 `forceOcrPages` |
| `describe` | ids + summary/tags | 补摘要/标签 |
| `trust` | ids + level/reason | 标可信度 |
| `keep` | ids | 标记重复已核对保留 |
| `remove` | ids + soft=true | 默认软删除 |

约束：

- 单批最多 50 篇；超限 413；
- `dryRun=true` 只校验/返回目标，不写；
- `readOnly` 库返回 409 `KB_READONLY`；
- 所有写动作先 `kb_snapshot`（或提示操作者先快照），写 log，刷新 index/FTS；
- 失败逐项汇总，不整批回滚（除 `describe` 批量可事务）；每项有 `ok/error`。

### 2.3 UI

在库详情新增「质量」tab（`#/kb/<name>/quality`）：

- 顶部：按 severity/组统计卡片；「仅看可操作」「仅看坏页」「仅看未编目」快捷筛选；
- 列表：标题、docId、组、证据、建议动作、更新时间；支持分页/搜索；
- 展开行：证据（页码、`contentIntegrity`、重复/相似匹配、缺摘要），按钮：
  - 查看原页（跳 `?doc=&page=` 深链）；
  - 重解析指定页（页码输入/多选）；
  - 补摘要（复用资料弹窗或内联表单）；
  - 标可信度 / `kb_keep` / 软删除；
- 操作栏：已选 N 篇、dry-run 预览、确认执行；执行结果逐项列出；
- 只读库：只展示，禁用动作并提示“只读共享”；
- 总览卡片可加“质量”小徽标（warning/error 数量），不阻塞打开库。

## 3. Runbook（必须包含人工步骤）

新增 `docs/reports/2026-11-02-standard-data-cleanup-runbook.md`，不要只写自动化命令。
结构：

### 阶段 0：准备（人工确认）

- `kb_snapshot(kb="标准", label="pre-quality-cleanup", includeSources=false)`；
- 记录基线：`kb_list` 总数、`kb_lint` 分组计数、坏页/不完整/未编目清单导出；
- 确认只处理 `标准` 库，测试库/真实其他库不动。

### 阶段 1：坏页（48 篇，人工判断 + 自动重解析）

- 按 `2026-11-01-bad-pages-incomplete-review.md` 分批；
- 34 篇 pdf-mixed 且坏页 ≤5：逐页 `kb_reparse forceOcrPages=...`；
- 5 篇混合且坏页 >5：整篇重解析；
- 9 篇扫描件：整篇 OCR；
- **人工**：表格/图形/空白页先 `kb_view`；可读则保留 flag，不重复 OCR；
- 每批后复查 `corrupted` 计数，记录新增/残留页。

### 阶段 2：正文不完整（19/23 篇，人工判断）

- 文字层失败 → `kb_reparse` / OCR；
- 封面-only（如 GB/T 528）→ 补完整源文件，不硬造正文；
- 说明/勘误/短文件 → 保持不动；
- **人工**：确认 chars/页、正文范围；源文件缺页时只记录缺口。

### 阶段 3：摘要（31 条，人工撰写）

- 打开前 1–2 页找“本文件规定了/适用于”；
- 写 1–2 句范围句，中文标准用“规定了…适用于…”；
- 扫描件无正文：用封面标题/范围，不编造；
- `kb_describe` 逐篇写回；每 10 篇抽查一次。

### 阶段 4：前缀/标准号（人工证据）

- 29 篇前缀不一致：看封面印刷前缀/年份；
- 封面与库内一致、站点不同 → 不改；
- 过程稿/报批稿 → 不改；
- 封面明确另一前缀 → 才 `kb_retitle`/修正标准号；
- 23 篇无标准号：规章/通知/内部稿不补号；标准类才补，未知不编造。

### 阶段 5：重复/多版本（人工核对）

- 同号同期同阶段：保留正确版本，`kb_keep` 或软删除；
- 同号不同年/阶段：保留两份，旧版按封面代替关系标 `low`；
- 不同语言/格式（IEC 62586-1/2）：`kb_keep`；
- 报批/征求意见稿不能作为废止依据。

### 阶段 6：验收

- `kb_lint` 分组计数对比基线；
- 抽查 `kb_query`/`kb_read`（坏页修复后正文/条款）；
- 跑 80 题检索回归；
- `kb_snapshot` 留清理后快照；
- 输出 `docs/reports/2026-11-02-standard-quality-cleanup-result.md`：处理数/保留数/未解决项。

## 5. 测试与验收

- API：`lintManifest` 13 组计数与现有 `kb_lint` 一致；`maxItems`/分页；只读接口无写；
- 动作：dryRun 零写入；单批 50 上限；readOnly 409；非法 action 400；失败逐项；
- UI：质量 tab 空态/有数据/筛选/深链/动作预览；E2E 覆盖坏页→查看→重解析入口；
- 性能：929 篇质量接口 < 500ms（本机）；
- 安全：所有写动作默认软删除；执行前快照；不自动改摘要/前缀/标准号；
- Runbook：在 `标准` 库完成只读预演，真实写入每批人工确认；最终计数与报告。
