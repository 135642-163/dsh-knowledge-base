## 2. kbpack 导出

`lib/store.js`：

- 新增 `buildKbpackManifest()` → `manifest.json`（`format=kbpack/v1`、`schemaVersion`、`parserVersion`、
  `kbName`、`exportedAt`、`exporter`、`withSources`、`counts`、`docs[]`）。
- `docs[]` 字段：`id/title/standardNo/type/kind/stage/sourceHash/textHash/contentHash/hashAlgo/chars/pages/parts/trust/sourceFile/hasSource/hasMarkdown/version/updatedAt`。
- `contentHash` 作为幂等键：优先 `sourceHash`，其次 `textHash`，笔记/旧文档退化为合并版 markdown 的 sha1。
- 软删除文档与失败文档不进包；`kb.json` 剔除 `sourcePath` 与 `history`；包内不含 `.std-check.json`、`.preview/`、`history/`。
- 导出仍走 `generateNodeStream` 流式写盘（`test/zip-stream.test.mjs` 的「禁止 generateAsync」守护仍通过）。

## 3. kbpack 导入

新文件 `lib/kbpack.js`；新工具 `kb_import_package`；`kb_import` 收到 `.zip` 自动路由。

- **安全**：`format=kbpack/v1`、`schemaVersion ≤ 6`（更高拒绝）；路径穿越/绝对路径/反斜杠/NUL/符号链接拒绝；
  条目数 ≤ 50k、解压后 ≤ 4GB、zip ≤ 1GB（内联解压上限，见 §7）。
- **冲突**：同 id 同内容幂等跳过；同 id 不同内容另分配 `docIdFor(id+"~imported")` 并保留两份；
  同标准号不同 id 复用 `scanDuplicates`（同库必跳过，跨库默认跳过并报告，`allowCrossDuplicates` 放行）；
  `replace` 需 `confirm:"replace"`，旧版进 history；`rename` 自动加「(导入)」后缀且不拦截跨库同号。
- **同名库由用户选**：目标库存在且 `mode` 省略 → **不写入**，返回 `merge` / `rename` / `replace` 三选一与说明；
  `dryRun=true` 只预演（不创建目标目录）。
- **落盘**：解压在锁外到 `import-tmp/package-*`，锁内 `commitDocs` **一次 manifest 写入**；包级互斥锁；
  >256 MB 自动走新 `lib/zip-reader.js` 流式读取（STORE/DEFLATE/ZIP64），不把 4.7 GB 整包读进内存；
  覆盖时自动快照历史；`title/summary/trust/standard` 的 `*Source=manual` 不覆盖目标库人工值（抽到 `buildDocEntry()` 统一实现）。
- **收尾**：笔记 `sources/linksOut` 随 id 重映射改写；`refreshKbIndex`；>200 篇转后台 FTS；`log.md` 记 `import-package`。
- **工作台入口**：概览页「导入知识库包」：上传 zip → 预检（同名库三选一）→ `kb-package` 后台任务导入；
  成功后清理上传文件，失败保留 24 小时；上传/导入均在 `.package-uploads/` 临时目录。
- **无 markdown 有 sources** 的文档走 `importFileInto` 重新解析（可 OCR）；两者皆无则跳过并提示。

## 4. kb_snapshot_restore

新文件 `lib/snapshot-restore.js`；新工具 `kb_snapshot_restore`。

- `list=true` 列快照；`snapshot` 唯一子串或 `latest=true`。
- 校验 `meta.json`/`kb.json`、路径安全、符号链接、`schemaVersion ≤ 6`、库名一致。
- 默认 `dryRun=true` 只报告新增/移除/变更/未变；`dryRun=false` 才写入。
- 恢复前自动 `before-restore-*` 快照；大快照（>256 MB）同样走流式 ZipReader；`prune=true` 时快照外文档 markdown 与 sources 移入
  `trash-restore/<时间戳>/`（不永久删）；`includeSources=true` 恢复快照内原件。
- 恢复后 `refreshKbIndex` + FTS（>200 篇后台）；`log.md` 追加 `snapshot-restore`；
  `log/schema/history` 不随快照回滚（避免抹掉恢复后的流水与人工编目历史）。

## 5. 用户追加需求

### 5.1 可信度人工可改

- 工作台资料弹窗新增「可信度」下拉（高/中/低/未标注），保存走 `PATCH metadata`；
- API 接受 `trust` / `trustReason`：写 `trustSource=manual`（`unknown` 写 `unknown`）、`trustUpdatedAt`，
  **不递增正文版本号**；
- 包导入/重解析不覆盖 `trustSource=manual`（`buildDocEntry` 统一保护）；`kb_trust` 工具行为不变。

### 5.2 OCR 前水印净化

- 新文件 `lib/watermark.js`：亮度直方图估计纸张/墨色；深色核心掩膜 + 半径 2 膨胀得到正文邻域；
  高于阈值且远离正文的像素置白；`auto` 只处理明显浅灰层，`strong` 可处理压在正文上的水印，`off` 关闭。
- 接入 `lib/parsers.js` 的 PDF 渲染：`pixmap.getPixels()` 为 wasm 堆视图，原地改后 `asPNG()` 供 OCR；
  **不写回原件**；只对走 OCR 的页生效，文字层页不受影响。
- 配置 `watermark`（默认 `auto`）+ `kb_import`/`kb_reparse` 参数；页级只记录「已去除水印 N 页」警告。
- 单测用合成页覆盖：浅灰/彩色水印、正文保留、干净页不动、低对比扫描跳过、auto 邻域保护 vs strong。

### 5.3 同名库导入由用户选择

见 §3：`mode` 三选一 + `dryRun` + `onTarget` 范围门（目标库越界在任何写入前拒绝）。

## 6. P1

- **缺口台账** `lib/gaps.js` + `<kb>/.std-gaps.json`：跨轮累计「站点未收录（排除站外体系）」与「分册歧义」，
  记录 `firstSeenAt/lastSeenAt/rounds/siteHit`；站点后续 `current/update/released/superseded/newer-in-kb`
  时自动移除；`runStdCheck` 结束时合并并写回，报告新增「缺口台账」行。
- **每日检查** `scripts/std-check-daily.mjs` + `scripts/com.dsh.kb-std-check.plist.example`：
  默认只检查，报告写 `docs/reports/std-check-YYYYMMDD.md`；仅 update/released 时 macOS 通知并退出码 10；
  Cookie 可来自 `--cookie` / `BZ_COOKIE` / `--profile` 的 `bzCookie`。
- **工作台「按标准号补下载」**：标准更新面板输入编号 → `POST /kbs/:kb/std-fetch` dryRun 同步检索并校验
  确认页/金币 → 用户确认后启动 `kb-std` 后台任务（复用现有轮询/取消/结果面板）；下载前仍做确认页
  标准号反查（防串档），结果回写 `.std-check.json`。

## 8. 已知限制与遗留

- **大包**：>256 MB 自动流式读取，上限 8 GB。JSZip 流式写盘在 >4 GB 时会把中央目录/本地头偏移按 32 位回绕
  （实测字段值 + 4 GB 才是真实偏移），本插件读取端已做回绕纠正；其他解压工具打开这类 >4 GB 包可能报错，
  跨工具迁移建议用正文包或按库拆分。
- **水印净化**：基于亮度/邻域的启发式，深灰水印、与正文大面积重叠、低对比扫描会保守跳过；已完成 6 页
  合成水印的 OCR A/B（CER 0.1221→0.1901→0.1490），但合成线与真实水印字形不同；仍缺人工标注的真实水印页 A/B。
- **快照恢复**：`log/schema/history` 不回滚；`before-restore` 快照默认不含 sources（恢复 sources 时建议同时确认）。
- **工作台**：暂无「上传 kbpack 包 + 三选一」的 UI（工具层已强制让用户选择）；「按标准号补下载」已做。
- **未改**：本轮未动 0.33 之前的遗留数据（GB/T 4728.12-2022、GB/T 31517.1-2022 补下载；DL/T 436-2021 另找来源；
  55 条封面核对不一致；320 篇占位 trustReason），真实库无写入。
