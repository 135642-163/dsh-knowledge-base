## 0. 先把边界说清楚

### 0.1 本次清理的硬约束

1. 只处理 `标准` 库；`历史`、`变电试验`、`电气一次`、`电气二次`、`电能质量`、`电气工程教材`、`Icon`、`default` 不动。
2. 每批写入前：先 dry-run 预览 → 我把批次表与预览发你 → 你回「确认第 N 批」→ 才执行。
3. 内容类动作（重解析/OCR）每批前留库级快照；元数据类动作（摘要/可信度/keep）
   **同样要快照**——它们不递增内容版本号，`kb_history` 回滚不了，只有库快照能退。
4. 默认软删除；永久删除不在本轮范围。
5. 不自动生成摘要、不自动改标题/标准号/可信度；这三类必须有人给出的证据。
6. 机器计数下降**不是**验收目标：坏页 flag 是「页面质量启发式」，表格/图形页
   即使 OCR 后文本可读，flag 仍会保留（2026-11-01 已实测 10 篇）。验收看「核对记录」而不是「归零」。

### 0.2 为什么坏页不能一把梭

`标准` 库 48 篇坏页文档**全部** `contentIntegrity=full`（正文完整），344 个坏页绝大多数是
**表格/图形/多栏页**。对这类页反复 OCR 的实测结果是：文本可读、置信度 94–97，
但启发式仍判 bad。所以阶段 1 的顺序永远是：

```
kb_view 看该页 → 判断（表格-可读 / 真空白 / 乱码 / 页缺失）→ 只有「乱码/空白且正文受影响」才 OCR
```

### 0.6 停止条件

出现以下任一项就停批、回报：

- dry-run 的有效/跳过与预期不一致（>10% 偏差）；
- 快照失败，或快照体积异常（明显小于 80 MB）；
- `kb_view` 看到的是空白页/缺页，但计划是 OCR（说明判断口径错了）；
- 同一篇在相邻两批都被判「乱码」——先停下来查是不是文字层问题，不要重复 OCR；
- 执行后组计数变化超出预期（例如删除后某组反而变多）。

### 1.2 人工判断步骤（每篇都做）

1. 打开该文档的坏页：`kb_view doc="<标题或ID>" page=<坏页>`。
   - 工作台等价路径：质量 tab → 坏页组 → 「查看原页」（会带页码）。
2. 回答一个问题：**这一页现在能不能读？**
   - 有可读文字（含 OCR 文本）、无 `U+FFFD`、表格结构能看懂 → **可读，保留 flag**。
   - 整页空白，或正文区域全是 `U+FFFD`/乱码，且该页内容对标准正文有用 → **需要 OCR**。
   - 页面是图形/电路图/公式版式，OCR 只会得到噪声 → **保留 flag**，引用时用原页。
   - 页码超出实际页数，或 `sources/` 里原件缺页 → **记录缺口，补源**，不硬造。
3. 只有第 2 步判定「需要 OCR」时，才进入 1.4 的命令。
4. 在附录 E 的坏页核对表里写一行：id / 页 / 判断 / 动作 / 依据。

> 判据不是主观感觉：截图或 `kb_view` 后要能指出「哪一行文字可读 / 哪里是乱码」。
> 判「保留 flag」时不用改动任何数据，这是 48 篇里多数文档的正确归宿。

### 1.4 决定「要 OCR」之后的命令

先 dry-run（**不发写入**；不传 `dryRun:false` 就是预览）：

```text
POST /kb/api/kbs/标准/quality/actions
{
  "action": "reparse-pages",
  "ids": ["<docId>"],
  "params": {}                     // 不传 pages = 自动取该文档坏页 ∪ 低置信页
}
```

确认后执行（同一接口，显式 `dryRun:false`）：

```text
{ "action": "reparse-pages", "ids": ["<docId>"], "params": { "snapshot": true }, "dryRun": false }
```

- `params.pages` 只在「只重识别其中几页」时手填（如 `"39,40"`）；批量多篇不要手填同一组页码。
- `params.forceOcr: true` = 整篇 OCR（用于扫描件正文为空）；耗时长，走后台 job。
- 也可用工具：`kb_reparse doc="<标题>" forceOcrPages="39,40"`（与 API 同一实现）。
- 图标：`ocrModel: "best"` 默认；`watermark` 默认 `auto`，干净 PDF 可用 `off`（水印实测见
  `2026-11-01-plugin-progress-and-manual-queue.md`）。

1. 先算「字数/页数」：`kb_read doc=... part=1` 看正文范围；对照上表。

| 场景 | 回滚方式 |
|---|---|
