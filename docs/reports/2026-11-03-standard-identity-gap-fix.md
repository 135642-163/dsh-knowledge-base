## 二、根因

1. **解析被文件名卡住（代码）**：`lib/pipeline.js` 的
   `standardEligible = kind !== "xlsx" && (filenameMeta.standardNo || epub/mobi)`
   只在**文件名已经带标准号**时才读正文/封面。Zotero 用「年份 - 名称」命名，文件名没有编号，
   于是封面上的 Q/GDW、GB/T 号永远不被读取；`lib/backfill.js` 是同一口径。
2. **后续步骤全部失效（流程放大）**：
   - `standardNo` 为空 → `trustHeuristic()` 返回 `unknown`，因此 2026-11-02 01:27 的批量
     `kb_trust(all=true)` 把这个 medium + 通用理由永久写在了这些**标准**上；
   - `kb_retitle` 只重写「标题能解析出编号」的资料，这些标题不会被补前缀；
   - `kb_lint` 的 `metadata-missing` 只在「标题能解析出号」时报，所以体检也看不出来。
3. **标题清洗漏项（代码）**：`cleanTitle` 不认 `2015 - ` 年份前缀、`(已作废)` 状态括注、
   `GBT+40600-2021`、末尾 `（GB/Z 17624.8-2025）`；`extractStdRef` 不认 `Q/HN` 一类企业标准前缀。

## 三、修复

### 3.1 插件（0.39.2，`PARSER_VERSION=2026-11-03.1`）

- `shouldParseContentStandard()`：文件名有号 / 标题像标准（通知、纪要、附件除外）/ 封面出现
  「中华人民共和国国家标准 / 企业标准 / 团体标准」横幅 → 才解析；文件名没有编号时
  `parseContentStandard(..., { coverOnly: true })` **只认封面区**（第一处 前言/目次/规范性引用文件 之前），
  防止把「规范性引用文件」表里的 GB/DL 号当成本文件的号。`pipeline.js`、`backfill.js` 同步。
- `cleanTitle()`：年份前缀、状态括注、`08-` 序号、`GBT+`、末尾括注编号（书名号标题保留）；
- `extractStdRef()`：支持 `Q/HN` 与通用 `Q/XXX` 企业标准前缀（`Q/HN-1-0000.08.021—2015`）；
- `kb_lint()`：新增「标题像标准，但没解析出标准号」分组（排除讲座/论文/介绍类标题）；
- 新增 `scripts/apply-doc-identity.mjs`：按人工核对表修正标题/标准号/可信度/摘要，
  每篇快照历史、重建 H1、版本 +1、刷新 index/log。

## 五、OCR 低置信假告警（GB/T 42737-2023 第 3 页）

- 现象：`kb_lint`「文字层损坏 / OCR 低置信」只剩 `532519050829`
  GB/T 42737-2023 电化学储能电站调试规程，低置信 1 页（第 3 页，OCR 置信度 60.3）。

- 修复：新增 `looksLikeBlankOcrText()`（`lib/parsers.js`）——OCR 文本 ≤24 字符且去掉
  水印/页码/标点/数字后不剩文字时判为空白页：正文写「（本页无文字内容）」、不计置信度、
  不进 `lowConfidencePages`；PDF 与 OFD 两条 OCR 质量统计同步。
- 重解析该文档（v3）：第 3 页 `{confidence: null, blank: true, text: "（本页无文字内容）"}`，
  `lowConfidencePages` 清零，全篇 OCR 平均置信度 97.4。
